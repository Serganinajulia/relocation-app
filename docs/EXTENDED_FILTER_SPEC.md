# Спецификация: Расширенный фильтр каталога городов — ReloCalc

*Зафиксировано: июль 2026 (v2 — с UI-паттернами и полным списком блоков)*

Этот документ фиксирует продуктовый дизайн расширенного фильтра — что должно быть в нём по смыслу и как оно выглядит, до того как соответствующие данные появятся в БД. Порядок работы: (1) спроектировать полный список категорий и UI — этот документ, (2) доработать БД под спроектированное, (3) реализовать фильтр одним спринтом.

Референс по духу — фильтр каталога на relokatz.com/catalog (структура блоков, часть формулировок).

---

## Общие UI-паттерны (действуют для всего фильтра)

- **Категориальные поля с несколькими значениями** (язык, климат, свобода, полит. режим, тур. виза, основания ВНЖ и т.п.) — выпадающий список с мультиселектом внутри (чекбоксы в открытой панели). Дефолт всегда "Любой/ая/ое" (фильтр не применяется, пока не выбрано хоть одно значение).
- **Индексы/уровни качества** (безопасность, медицина, образование, счастье, сила паспорта) — выпадающий список с готовыми уровнями-порогами: "Любой / Допустимый (от X) / Высокий (от Y)". Точные пороги X/Y — калибруются на реальных данных после наполнения БД.
- **Бесплатность** (медицина, сад, школа) — отдельные чекбоксы, независимые от индексов качества. Оба типа фильтра (бесплатно vs качество) сосуществуют, не взаимоисключают друг друга.
- **Числовые диапазоны без естественных категорий** (температура лета/зимы) — два счётчика (от/до) с шагом 1°, поля стартуют **пустыми** (не предзаполненными), с зафиксированными разумными границами ввода (например, −40…+50°C — не дают ввести абсурдное значение).
- **Бюджет** — степпер (−/значение/+), визуально идентичный полю бюджета в быстром фильтре, не слайдер.
- **Гражданство (сроки)** — пилюли с накопительным порогом: Любое / До 2 лет / До 5 лет / До 10 лет / От 10 лет. "До 5 лет" включает все страны с меньшим сроком тоже (не узкий диапазон 3–5).
- **Выбранные значения "улетают" пилюлями наверх фильтра**, под заголовок "Фильтры", в отдельную зону "Выбрано" — с крестиком на каждой пилюле для быстрого снятия конкретного фильтра.

## Блок 1. Бюджет

Дублирует поле "Ежемесячный бюджет" из быстрого фильтра (степпер) — для удобства при работе через расширенный фильтр отдельно от быстрого (актуально на мобилке).

---

## Блок 2. Страны и языки

- **Выбор стран** — выпадающий список, мультиселект, двухуровневая структура: сначала кластеры, затем отдельные страны под каждым.
  - **Готово:** `country_clusters` (справочник) + `countries.cluster_id` — созданы и заполнены. Кластеры пользовательские, географическо-исторические (не строго географические и не политико-экономические): Латинская Америка, Евросоюз, Бывший СНГ, Азия (последний пока без стран — задел на будущее).
- **Официальные языки** — выпадающий список, мультиселект, по `country_languages` → `languages`.
- **Уровень английского** — выпадающий список (Любой/Высокий/Средний/Низкий) по `cities.english_level` — готово.

---

## Блок 3. Климат и природа

- **Тип климата** — выпадающий список, мультиселект, по `climate_type_id` → `climate_types` (4 категории; заполнено 11/16 городов).
- **Природа** — выпадающий список, мультиселект (Море/Горы) — по `sea_type`, `has_mountains` — готово.
- **Экология** — выпадающий список с уровнями (Любая/Допустимая/Высокая).
  - **Готово:** `cities.ecology_index` (0-100) — колонка создана, ждёт наполнения данными (см. comment на колонке в БД — источник Numbeo Environment Index).
- **Температура летом** — два счётчика "от"/"до", пустые по умолчанию, шаг 1°, границы ввода (−40…+50) — по `temp_summer_min/max`, поля есть, UI отсутствует.
- **Температура зимой** — аналогично, по `temp_winter_min/max`.

---

## Блок 4. Политика и безопасность

- **Свобода** — выпадающий список, мультиселект, по `country_politics.fh_status_id` → `fh_statuses` (Свободная/Частично свободная/Несвободная) — готово.
- **Политический режим** — выпадающий список, мультиселект, по `eiu_regime_type_id` → `eiu_regime_types` — готово (уже отображается тегом в `CityCard`, не используется как фильтр).
- **Безопасность** — выпадающий список с уровнями (Любая/Допустимая (от X)/Высокая (от Y)) по `safety_index` — готово, нужны только пороги.
- **Индекс счастья** — выпадающий список с уровнями, аналогично безопасности.
  - **Готово:** `cities.happiness_index` (0-100) — колонка создана на уровне города (не страны — счастье варьируется от места к месту сильнее, чем между соседними странами), ждёт наполнения данными.

---

## Блок 5. Легализация и гражданство

Порядок внутри блока: туристические визы → основания для ВНЖ → фильтр "доход подходит" → сила паспорта → гражданство (сроки) → налоги.

- **Туристическая виза** — выпадающий список, мультиселект (Любая/Безвизовый въезд/Условный безвиз/Шенген и т.п. — по факту заполненных `visa_type` в `tourist_visas`) — готово.
- **Основание для ВНЖ** — выпадающий список, мультиселект, по `residency_types` (точный список — открытый вопрос, см. ниже).
  - **"Особые программы"** (стартапер/пенсионер/эксперт/молодёжь/рантье) — НЕ отдельный список данных, а альтернативный вход в тот же справочник оснований, переформулированный "от профиля человека" вместо "от типа основания". Реализуется как UI-надстройка, не требует отдельной таблицы.
  - **Требует новых данных:** `residency_types` и `country_residency_options` сейчас пустые (0 записей) — нужно наполнить с нуля.
- **Чекбокс "Доход семьи подходит"** — независимый активный фильтр (не привязан к тому, выбрано ли конкретное основание вручную): показывает только те основания/страны, где доход/бюджет семьи проходит порог `min_income_usd` — **по всем** основаниям сразу, а не только по выбранному. Логика похожа на `getBudgetStatus`, но сравнение идёт с порогом визовой программы, а не со стоимостью жизни.
- **Сила паспорта** — выпадающий список с уровнями (Любая/Средняя (от X)/Сильная (от Y)) по `passport_strength` — готово, нужны пороги.
- **Гражданство (сроки)** — пилюли, накопительный порог: Любое / До 2 лет / До 5 лет / До 10 лет / От 10 лет — по `citizenship_years` — готово.
- **Налоги** — чекбокс/выпадающий список по `remote_income_tax_type` (например "не облагает налогом удалённый доход") — данные есть, UI отсутствует.

## Блок 6. Медицина и образование

- **Уровень медицины** — выпадающий список с уровнями (Любой/Допустимый/Высокий).
  - **Готово:** `cities.healthcare_quality_index` (0-100) — на уровне города (бесплатность/доступность остаётся отдельным полем `countries.healthcare_access` на уровне страны — законодательный статус; качество варьируется по городской инфраструктуре). Ждёт наполнения данными.
- **Уровень образования** — выпадающий список с уровнями, аналогично.
  - **Готово:** `cities.education_quality_index` (0-100) — та же логика, на уровне города, отдельно от `countries.kindergarten_is_free`/`school_is_free`. Ждёт наполнения данными.
- **Бесплатная медицина** — отдельный чекбокс, по `healthcare_access` — готово (тот же источник, что и в расчёте бюджета).
- **Бесплатный сад** — чекбокс, по `kindergarten_is_free` — готово.
- **Бесплатная школа** — чекбокс, по `school_is_free` — готово.

## Панель над каталогом (не часть сайдбара, отдельный элемент)

Строка над сеткой карточек: **"Подходящих городов: N"** слева, **"Сортировка по: ..."** справа (выпадающее меню).

Варианты сортировки: Популярность (дефолт), Арендная плата, Безопасность, Свобода (по `fh_score`, не по категориальному режиму), Индекс счастья, Качество жизни, Медицина, Образование, Экология, Стоимость жизни, Бюджет в месяц.

**Требует новых данных:** "Качество жизни" — отдельный сводный индекс, которого нет в схеме — нужно решить, это агрегат из других индексов (безопасность+медицина+экология и т.п.) или отдельная независимая метрика.
