# Архитектура: Стили жизни, сравнение бюджета и фильтрация каталога — ReloCalc

*Зафиксировано: июль 2026*

Этот документ фиксирует решения, принятые в ходе обсуждения системы фильтрации каталога городов по бюджету и стилю жизни. Служит опорой перед реализацией и для восстановления контекста в новых сессиях.

---

## 1. Стили жизни

**Системные пресеты** (без изменений в базовой логике):

```ts
type SystemLifestyle = 'economy' | 'comfort' | 'comfort_plus'

```

**Кастомные стили** — пользователь может создать до **3** собственных именованных стилей жизни через модал "Задать свой стиль".

- Кастомный стиль можно создать с нуля, либо взяв за основу один из системных пресетов (тогда модал открывается с предзаполненными значениями пресета, которые пользователь дальше может менять).
- У кастомного стиля есть название, которое задаёт пользователь (например: "Мой стиль", "С садиком", "Без такси").
- Кастомные стили отображаются в общем списке стилей жизни наравне с системными (в переключателе и при выборе для сравнения).

`any` **("Любой") — убран из списка стилей жизни.** Его функцию полностью забирает механизм сравнения (см. раздел 4).

Переключатель стиля жизни в быстром фильтре: `Эконом / Базовый (дефолт) / Комфорт+ / [Кастомный 1] / [Кастомный 2] / [Кастомный 3] / Задать свой (beta)`.

---

## 2. Расширенный фильтр — только условия отбора города

Расширенный фильтр **больше не содержит калькуляционных параметров** (кафе, такси, фитнес и т.п.). Он остаётся только про то, что не влияет на расчёт бюджета, а фильтрует по условиям проживания:

- климат и природа
- легализация / визовые условия
- тип жилья, спальни
- прочие некалькуляционные условия (свобода, безопасность и т.п., если появятся)

Вся калькуляционная кастомизация (сколько походов в кафе, включён ли коворкинг, нужен ли платный сад/школа и т.д.) переезжает в модал **"Задать свой стиль"** (раздел 3).

---

## 3. Модал "Задать свой стиль жизни"

Открывается по кнопке "Задать свой" в переключателе стилей. Содержит все кастомизируемые статьи расчёта из `formulas.ts`, кроме тех, что не зависят от стиля жизни напрямую (аренда и коммуналка зависят от типа жилья, а не от стиля — см. раздел 7).

**Независимость от пресета.** Пресет, выбранный на момент открытия модала, — это только точка старта (дефолтные значения полей формы). После сохранения кастомный стиль хранит **полный набор значений всех полей**, а не diff/оверрайд поверх пресета. Никакой связи с исходным пресетом после сохранения не остаётся — если системные коэффициенты пресетов изменятся в будущем, уже созданные кастомные стили пользователей не должны измениться.

**UX создания названия — двухступенчатый оверлей поверх формы:**

1. Пользователь настраивает поля формы, жмёт кнопку **"Создать стиль"**.
2. Поверх формы (не вместо неё) появляется затемнённый/блюрный слой с полем ввода "Введите своё название стиля" (лимит — **16 символов**, жёсткое ограничение ввода через `maxLength`) и кнопками **"Готово"** / **"Отменить"**.
3. **"Готово"** → стиль сохраняется с введённым именем, модал закрывается.
4. **"Отменить"**, крестик, или клик по оверлею вне плашки → оверлей с названием исчезает, пользователь возвращается к форме — значения полей сохраняются, ничего не теряется.

Логика создания:

- **С нуля** — все параметры на нейтральных/дефолтных значениях.
- **На основе пресета** — пользователь сначала выбирает системный пресет, кликает "Задать свой", модал открывается с предзаполненными значениями этого пресета как стартовыми — дальше свободное редактирование, итоговый стиль независим (см. выше).

Лимит: **до 3 кастомных стилей** на пользователя.

**Редактирование и удаление.** У каждого кастомного стиля в переключателе — иконки "Редактировать" и "Удалить" в правом верхнем углу его таблетки. Редактирование открывает тот же модал, предзаполненный текущими значениями стиля. Удаление показывает подтверждение перед необратимым действием.

## 4. Сравнение нескольких стилей с бюджетом

**Кнопка сравнения появляется только когда введён бюджет.** Без бюджета — просто отображается стоимость выбранного (одного) стиля жизни, без подсветки, без сравнения.

Когда бюджет введён:

- По умолчанию — показывается стоимость **того одного** стиля, что выбран в переключателе, с подсветкой запаса (раздел 5).
- Появляется кнопка (формулировка уточняется, рабочий вариант: **"Сравнить несколько стилей с моим бюджетом"**), по клику — мультиселект, где можно отметить **до 3** стилей (системные и/или кастомные, в любой комбинации).
- При выборе нескольких — карточка показывает **по одной строке на каждый выбранный стиль**, каждая строка подсвечена отдельно (раздел 5).

---

## 5. Подсветка запаса бюджета

Единая функция статуса, применяется к любому стилю (при одиночном отображении — один раз, при сравнении — к каждой выбранной строке отдельно):

```ts
function getBudgetStatus(budget: number, cost: number): 'exceeds' | 'comfortable' | 'tight' | 'insufficient'

```

- Пороги — **гибрид** (Вариант 3): процент от бюджета + нижний "пол" в долларах для очень маленьких бюджетов. Точные цифры порогов калибруются позже на реальных данных по городам.
- `insufficient` — бюджет не дотягивает даже до этого стиля.

**Буфер/погрешность на границе (условно $50–100 или ~10%) — обсуждался, но отложен.** В первой версии фильтрация бинарная, без "полупрозрачного" промежуточного статуса. Вернуться к этому вопросу после того, как увидим реальные данные и частоту пограничных случаев.

## 6. Правило отсева городов из каталога

Бинарное, без буфера:

```
minCost = min(cost по всем стилям, выбранным для сравнения — или по одному выбранному, если сравнение не активно)
budget < minCost  → город не показываем в каталоге вообще
budget >= minCost → город показываем, с подсветкой по каждому выбранному стилю

```

Если бюджет не введён — фильтрации по бюджету нет, показываются все города (с учётом остальных фильтров — климат, легализация и т.п.).

## 7. Коммунальные услуги — масштабирование по стилю

**Решение: коммуналка масштабируется по стилю жизни аналогично аренде** (расхождение с изначальной версией `FORMULAS.md`, где было "фиксировано, всегда `utilities_usd_min`").

```
Эконом      = utilities_usd_min
Базовый     = (utilities_usd_min + utilities_usd_max) / 2
Комфорт+    = utilities_usd_max

```

**Требуется:**

- Обновить `FORMULAS.md` (раздел 3).
- В `formulas.ts`: добавить `utilities_usd_max` в `CalcInput`, завести `calcUtilities()` по аналогии с `calcRent()`, заменить `const utilities = input.utilities_usd_min` на вызов новой функции.

## 8. Детский сад / школа в стиле "Эконом" — подтверждённое поведение

Существующая логика в `formulas.ts` подтверждена как намеренная (расхождение с `FORMULAS.md`, который тоже нужно актуализировать):

```ts
if (lifestyle === 'economy') return 0

```

То есть в Экономе по умолчанию сад/школа не оплачиваются (даже если в стране это платно) — расчёт исходит из того, что в этом стиле жизни ребёнок не ходит в частный сад/школу. Если пользователь в кастомизации (модал "Задать свой стиль", раздел 3) явно включает сад/школу поверх эконома — тогда стоимость добавляется.

**Требуется:** дописать это правило в `FORMULAS.md` (разделы 12–13).

---

## 9. Сохранение кастомных стилей и фильтров

- **Гость (не авторизован)** — сохранение в localStorage.
- **Авторизованный пользователь** — сохранение в Supabase (таблица вроде `saved_lifestyles` / `saved_filters`, привязка к `user_id`).
- **Миграция localStorage → Supabase при регистрации/входе — не делаем в первой версии.** Если гость создал кастомные стили локально, а потом зарегистрировался — старые локальные данные не переносятся автоматически. Это можно добавить позже как отдельную доработку.
- Нужно уточнить: настроена ли в проекте авторизация через Supabase Auth уже сейчас, или это отдельный самостоятельный сплит перед тем, как строить сохранение.

## Дорожная карта реализации (по приоритету, от простого к сложному)

1. **Коммуналка** — правки в `formulas.ts` + `CalcInput` (раздел 7). Не зависит ни от чего остального, можно закрыть первым.
2. Актуализация `FORMULAS.md` — коммуналка (п.7) + сад/школа в экономе (п.8), одним заходом.
3. Структура `userOverrides` / модель кастомного стиля жизни — типы данных для модала "Задать свой стиль" (раздел 3).
4. Расчётный слой — функция подсчёта стоимости для набора стилей (1 или до 3), с учётом кастомных.
5. `getBudgetStatus()` — функция подсветки (раздел 5).
6. Правило отсева городов (раздел 6) — интеграция в логику каталога.
7. UI: кнопка "Сравнить несколько стилей" + мультиселект (раздел 4).
8. UI: модал "Задать свой стиль жизни" (раздел 3).
9. Уточнить состояние авторизации в проекте → спроектировать `saved_lifestyles` в Supabase + localStorage-версию для гостя (раздел 9).
